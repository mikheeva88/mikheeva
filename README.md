# Эмулятор командной строки

Практическая работа №1 по дисциплине «Конфигурационное управление»,
вариант 18: эмулятор языка оболочки UNIX-подобной ОС.

Реализованы Этапы 1-4: REPL, конфигурация, VFS из ZIP-архива, команды
`ls`, `cd`, `echo`, `tac`.

## Общее описание

Приложение с графическим окном (tkinter). Команды вводятся в строку
внизу окна, результат выводится выше, как в терминале. Заголовок окна
берётся у реальной ОС: `Эмулятор - [username@hostname]`. Приглашение
показывает текущий каталог: `user@host:/home/user$`.

VFS загружается из ZIP-архива в память при запуске. Все команды
работают только с данными в памяти: архив только читается, на диск
ничего не распаковывается и не записывается.

Весь код программы находится в одном файле `src/emulator.py`.

## Параметры командной строки

| Параметр | Описание |
|---|---|
| `--vfs PATH` | путь к ZIP-архиву с VFS |
| `--script PATH` | путь к стартовому скрипту |
| `-h`, `--help` | справка |

Параметры необязательны, порядок любой, допустима запись `--vfs=PATH`.
Если `--vfs` не задан, VFS пустая. При запуске в окне выводятся
значения всех параметров (отладочный вывод):

```
[debug] Параметры запуска:
[debug]   --vfs    = vfs_data\deep.zip
[debug]   --script = examples\main_commands.txt
```

Неизвестный параметр или параметр без значения: сообщение об ошибке в
консоли, окно не открывается. Если архив не найден, повреждён или
содержит запись с `..` в пути, в окне выводится ошибка красным цветом,
а эмулятор продолжает работу с пустой VFS.

## Стартовый скрипт

Текстовый файл (UTF-8), по одной команде в строке. Команды
выполняются по очереди, в окне виден и ввод, и вывод. Пустые строки и
строки, начинающиеся с `#`, пропускаются. Строка с ошибкой не
останавливает скрипт: сообщение выводится красным цветом, затем
выполняется следующая строка. Команда `exit` завершает скрипт и
закрывает эмулятор. Если файл скрипта не найден, выводится ошибка, и
эмулятор работает в интерактивном режиме.

## Команды

| Команда | Описание |
|---|---|
| `ls [ПУТЬ]` | содержимое каталога (по строке на имя, каталоги со «/»); для файла выводится его имя |
| `cd [ПУТЬ]` | смена текущего каталога; без аргумента переход в корень |
| `echo [СЛОВО...]` | вывод аргументов через пробел |
| `tac ФАЙЛ...` | строки каждого файла в обратном порядке |
| `exit` | завершение работы |

- Пути бывают абсолютными (`/a/b`) и относительными (от текущего
  каталога), поддерживаются `.` и `..`.
- Кавычки (`"..."`, `'...'`) объединяют слова в один аргумент.
  Незакрытая кавычка даёт синтаксическую ошибку.
- `tac`: каждый файл переворачивается отдельно. Двоичные файлы
  выводятся в base64. Пустой файл ничего не выводит.
- Ошибки (красным цветом): путь не найден, лишние аргументы, `cd` в
  файл, `tac` на каталог или без аргументов, неизвестная команда.
  Если у `ls` или `tac` какой-либо путь не найден, выводится только
  ошибка.

## Структура проекта

```
src/emulator.py       весь код эмулятора
tests/test_emulator.py  модульные тесты
tools/make_vfs.py     генератор тестовых ZIP-архивов
examples/             стартовые скрипты эмулятора (.txt)
scripts/              скрипты Windows для проверки (.bat)
run.bat               запуск эмулятора
```

Основные функции `src/emulator.py`: `load_vfs` (загрузка ZIP в память),
класс `Shell` (текущий каталог и команды `cmd_ls`, `cmd_cd`,
`cmd_echo`, `cmd_tac`, `cmd_exit`, метод `run`), `read_script` и
`script_commands` (стартовый скрипт), `parse_args` и `format_debug`
(параметры), класс `App` (окно).

## Требования

Python 3.8 или новее с модулем tkinter (в Windows входит в
стандартную установку). Сторонние библиотеки не нужны.

## Запуск

Сборка не требуется.

```
run.bat
run.bat --vfs vfs_data\deep.zip --script examples\main_commands.txt
```

или

```
python src\emulator.py --vfs vfs_data\deep.zip
```

ZIP-архивы не хранятся в репозитории, их создаёт генератор (папка
`vfs_data` игнорируется git):

```
python tools\make_vfs.py
```

| Архив | Содержимое |
|---|---|
| `minimal.zip` | один файл |
| `several.zip` | несколько файлов (текст, пустой, двоичный) и каталог |
| `deep.zip` | вложенность 5 уровней, пустой каталог, двоичный файл |
| `broken.zip` | не ZIP-архив (для проверки ошибки) |
| `traversal.zip` | запись `../evil.txt` (для проверки ошибки) |

## Тесты

```
set PYTHONPATH=src
python -m unittest discover -s tests -v
```

Скрипты Windows в `scripts/` сами создают архивы и по очереди
запускают эмулятор (после закрытия окна начинается следующий запуск):

| Скрипт | Что проверяет |
|---|---|
| `test_basic.bat` | без параметров, только `--vfs`, только `--script`, оба |
| `test_errors.bat` | ошибки скрипта, нет файла скрипта, `exit`, неизвестный параметр |
| `test_syntax.bat` | `--параметр=значение`, порядок, параметр без значения, `--help` |
| `test_vfs_minimal.bat` | минимальная VFS |
| `test_vfs_several.bat` | несколько файлов |
| `test_vfs_deep.bat` | вложенность не менее трёх уровней |
| `test_vfs_errors.bat` | нет архива, не ZIP, опасный путь, нет `--vfs` |
| `test_stage4.bat` | все режимы `ls`, `cd`, `echo`, `tac` и ошибки |

Скрипт `examples/main_commands.txt` проверяет все команды Этапа 4 с
ошибками, остальные скрипты в `examples/` используются скриптами выше.

## Примеры

```
user@host:/$ ls
etc/
home/
readme.txt
user@host:/$ cd home/user/docs
user@host:/home/user/docs$ ls
archive/
report.txt
отчёт.txt
user@host:/home/user/docs$ tac report.txt
Строка 2
Отчёт
user@host:/home/user/docs$ cd ../../..
user@host:/$ tac etc/blob.bin
(двоичный файл, base64)
//4AAQoaColQTkcN
user@host:/$ echo "много   пробелов"
много   пробелов
user@host:/$ cd readme.txt
cd: readme.txt: не каталог
user@host:/$ foo
foo: команда не найдена
user@host:/$ exit
```

Последняя команда закрывает окно.
