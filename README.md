# Эмулятор командной строки

Практическая работа №1 по дисциплине «Конфигурационное управление»,
вариант 18: эмулятор языка оболочки UNIX-подобной ОС. Реализованы
Этапы 1-5.

## Общее описание

Приложение с графическим окном (tkinter). Команды вводятся в строку
внизу окна, результат выводится выше, как в терминале. Заголовок окна
берётся у реальной ОС: `Эмулятор - [username@hostname]`. Приглашение
показывает текущий каталог: `user@host:/home/user$`.

VFS загружается из ZIP-архива в память. Все команды, в том числе
изменяющие VFS (`rmdir`, `chown`), работают только с данными в памяти:
архив только читается и не распаковывается. После перезапуска VFS снова
такая, как в архиве. Весь код находится в `src/emulator.py`.

## Параметры запуска

| Параметр | Описание |
|---|---|
| `--vfs PATH` | путь к ZIP-архиву с VFS (без него VFS пустая) |
| `--script PATH` | путь к стартовому скрипту |
| `-h`, `--help` | справка |

При запуске в окне выводятся значения всех параметров:

```
[debug] Параметры запуска:
[debug]   --vfs    = vfs_data\deep.zip
[debug]   --script = examples\main_commands.txt
```

Неизвестный параметр или параметр без значения: ошибка в консоли, окно
не открывается. Если архив не найден, повреждён или содержит путь с
`..`, в окне выводится красная ошибка, эмулятор работает с пустой VFS.

**Стартовый скрипт** это текстовый файл (UTF-8) с командами, по одной в
строке. Команды выполняются по очереди, в окне видны ввод и вывод.
Пустые строки и строки с `#` в начале пропускаются. Строка с ошибкой не
останавливает скрипт: ошибка выводится красным, затем выполняется
следующая строка. `exit` закрывает эмулятор. Если файла скрипта нет,
выводится ошибка и эмулятор работает в интерактивном режиме.

## Команды

| Команда | Описание |
|---|---|
| `ls [-l] [ПУТЬ]` | содержимое каталога (по строке на имя, каталоги со «/») или имя файла; `-l` добавляет тип (`d`, `-`), владельца, группу, размер |
| `cd [ПУТЬ]` | смена каталога; без аргумента переход в корень |
| `echo [СЛОВО...]` | вывод аргументов через пробел |
| `tac ФАЙЛ...` | строки каждого файла в обратном порядке |
| `rmdir КАТАЛОГ...` | удаление пустых каталогов |
| `chown ВЛАДЕЛЕЦ[:ГРУППА] ПУТЬ...` | смена владельца (и группы) |
| `exit` | завершение работы |

- Пути бывают абсолютными (`/a/b`) и относительными, поддерживаются
  `.` и `..`. Кавычки объединяют слова в один аргумент.
- `tac` переворачивает каждый файл отдельно, двоичные файлы выводит в
  base64. Пустой файл ничего не выводит.
- `chown`: по умолчанию у всех `root root`, если группа не указана, она
  не меняется. Пути проверяются заранее, при ошибке ничего не
  меняется. Результат виден в `ls -l`.
- `rmdir` удаляет каталоги по очереди, при ошибке останавливается.
  Нельзя удалить корень, текущий и непустой каталог.
- Ошибки выводятся красным: путь не найден, лишние или недостающие
  аргументы, `cd` в файл, `tac` на каталог, неверный ключ, неизвестная
  команда, незакрытая кавычка. У `ls` и `tac` при ошибке выводится
  только ошибка.

Основные функции `src/emulator.py`: `load_vfs` (ZIP в память: каталог
это `dict`, файл это `bytes`), класс `Shell` (текущий каталог, владельцы
и команды `cmd_*`), `read_script`, `parse_args`, класс `App` (окно).

## Структура

```
src/emulator.py   весь код
tests/            модульные тесты
tools/make_vfs.py создание тестовых ZIP-архивов
examples/         стартовые скрипты эмулятора (.txt)
scripts/          скрипты Windows для проверки (.bat)
run.bat           запуск эмулятора
run_tests.bat     запуск тестов
```

## Запуск и тесты

Нужен Python 3.8+ с tkinter (в Windows входит в установку). Сборка не
требуется. ZIP-архивы в репозитории не хранятся, их создаёт скрипт
(папка `vfs_data` игнорируется git).

```
python tools\make_vfs.py
run.bat --vfs vfs_data\deep.zip --script examples\main_commands.txt
run_tests.bat
```

Архивы: `minimal.zip` (один файл), `several.zip` (несколько файлов),
`deep.zip` (5 уровней, пустые каталоги, двоичный файл), `broken.zip` (не
ZIP) и `traversal.zip` (путь с `..`) для проверки ошибок.

Скрипты `scripts\*.bat` сами создают архивы и по очереди запускают
эмулятор (следующий запуск начинается после закрытия окна):

| Скрипт | Что проверяет |
|---|---|
| `test_params_1.bat` | запуск без параметров, только `--vfs`, только `--script`, оба |
| `test_params_2.bat` | `--параметр=значение`, порядок, скрипт с ошибками и `exit`, нет скрипта, неизвестный параметр, `--help` |
| `test_vfs_1.bat` | минимальная VFS, несколько файлов, 5 уровней |
| `test_vfs_2.bat` | команды на трёх VFS, нет архива, не ZIP, опасный путь |
| `test_commands.bat` | Этапы 4 и 5; повторный запуск показывает, что архив не изменился |

Стартовые скрипты Этапов 4 и 5: `examples\main_commands.txt` (`ls`,
`cd`, `echo`, `tac`) и `examples\stage5_commands.txt` (`rmdir`, `chown`,
`ls -l`): все режимы команд и ошибки.

## Примеры

```
user@host:/$ ls
etc/
home/
readme.txt
tmp/
user@host:/$ cd home/user/docs
user@host:/home/user/docs$ tac report.txt
Строка 2
Отчёт
user@host:/home/user/docs$ chown bob:staff report.txt
user@host:/home/user/docs$ ls -l
d root root      0 archive/
- bob staff     26 report.txt
- root root     33 отчёт.txt
user@host:/home/user/docs$ cd /
user@host:/$ rmdir tmp/a tmp/b
user@host:/$ rmdir tmp
user@host:/$ rmdir home
rmdir: home: каталог не пуст
user@host:/$ tac etc/blob.bin
(двоичный файл, base64)
//4KGgqJUE5HDQ==
user@host:/$ echo "много   пробелов"
много   пробелов
user@host:/$ foo
foo: команда не найдена
user@host:/$ exit
```

Последняя команда закрывает окно.
