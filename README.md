# Эмулятор командной строки

Практическая работа №1 по дисциплине «Конфигурационное управление»,
вариант 18: эмулятор языка оболочки UNIX-подобной ОС.

Реализовано:

- Этап 1: REPL (графический интерфейс, парсер, команды ls, cd, exit);
- Этап 2: конфигурация (параметры командной строки, стартовый скрипт,
  отладочный вывод параметров);
- Этап 3: виртуальная файловая система (VFS), загружаемая из
  ZIP-архива в память.

## Общее описание

Эмулятор с графическим интерфейсом (tkinter). Пользователь вводит
команды в строку внизу окна, результат выводится в область над ней,
как в обычном терминале (REPL: прочитать команду, выполнить, вывести
результат, повторить).

Заголовок окна формируется из реальных данных ОС:
`Эмулятор - [username@hostname]`.

Команды `ls` и `cd` пока являются заглушками: они выводят своё имя и
аргументы (их логика будет работать с VFS на Этапе 4). Для проверки
загруженной VFS добавлены служебные команды `vfs-info`, `vfs-tree` и
`vfs-show`.

```
src/emulator/script.py        чтение и выполнение стартового скрипта
```

## Описание функций и настроек

### Параметры командной строки (`config.py`)

| Параметр | Описание |
|---|---|
| `--vfs PATH` | путь к ZIP-архиву с VFS |
| `--script PATH` | путь к стартовому скрипту |
| `-h`, `--help` | справка по параметрам |

Оба параметра необязательны, порядок любой, допустима запись
`--vfs=PATH`. Сокращённые имена (`--vf`) не поддерживаются. При
неизвестном параметре или параметре без значения программа выводит
сообщение об ошибке в консоль и завершается, окно не открывается.

**Отладочный вывод.** При запуске в окне показываются значения всех
параметров (не заданные помечаются `(не задан)`):

```
[debug] Параметры запуска:
[debug]   --vfs    = vfs_data\deep.zip
[debug]   --script = examples\all_commands.txt
```

### VFS (`vfs.py`)

VFS загружается из ZIP-архива при запуске, если задан `--vfs`.
Все данные хранятся в оперативной памяти: архив только читается, на
диск ничего не распаковывается и не записывается. Архив не
изменяется.

- Поддерживаются каталоги (явные записи вида `dir/` и неявные, которые
  появляются из путей файлов), пустые каталоги, вложенность до 100
  уровней, имена на кириллице (UTF-8).
- Содержимое файлов хранится как байты. Двоичные данные при выводе
  кодируются в base64 (см. `vfs-show`).
- Ошибки загрузки: файл не найден, не является ZIP-архивом, архив
  повреждён, запись с `..` в пути (выход за корень), конфликт имени
  файла и каталога, повтор записи, слишком большая вложенность. В
  этом случае выводится сообщение красным цветом, а эмулятор
  продолжает работу без VFS.
- При успешной загрузке выводится строка с числом каталогов и файлов.

Функции модуля: `load_vfs(path)` загрузка, `Vfs.find(path)` поиск
узла, `Vfs.stats()` статистика.

### Служебные команды VFS (`vfs_commands.py`)

Команды только читают VFS и ничего в ней не изменяют. Пути
записываются от корня VFS (`/a/b` или `a/b`).

| Команда | Описание |
|---|---|
| `vfs-info` | источник VFS, число каталогов (без корня), файлов, общий размер |
| `vfs-tree` | дерево каталогов и файлов с размерами |
| `vfs-show ПУТЬ` | содержимое файла: текст как есть, двоичные данные в base64, пустой файл помечается `(файл пуст)` |

Ошибки (красным цветом): VFS не загружена; лишние аргументы у
`vfs-info` и `vfs-tree`; у `vfs-show` не один аргумент, путь не
найден или это каталог.

### Стартовый скрипт (`script.py`)

Стартовый скрипт это текстовый файл (UTF-8), по одной команде эмулятора
в строке. После запуска окна команды выполняются последовательно, на
экране видно и введённую строку, и результат, как в диалоге с
пользователем (между строками небольшая пауза).

- пустые строки и строки-комментарии (начинаются с `#`) пропускаются;
- строка с ошибкой (неизвестная команда, неверные аргументы) не
  прерывает скрипт: сообщение об ошибке выводится красным цветом, затем
  выполняется следующая строка;
- команда `exit` завершает скрипт и закрывает эмулятор;
- если файл скрипта не найден или не читается, выводится сообщение
  об ошибке, и эмулятор продолжает работу в интерактивном режиме;
- после выполнения последней строки эмулятор остаётся открытым.

### Команды (`commands.py`)

- `ls [args...]` заглушка: выводит имя команды и аргументы.
- `cd [args...]` заглушка: выводит имя команды и аргументы.
- `exit` завершает работу эмулятора. Если переданы аргументы, выводит
  ошибку «слишком много аргументов» и не завершается.
- Неизвестная команда: сообщение `<имя>: команда не найдена`.
- Пустая строка: ничего не происходит.

### Парсер (`shell_parser.py`)

`parse_line(line)` делит строку по пробельным символам: первое слово
команда, остальные аргументы. Несколько пробелов подряд считаются
одним разделителем. Кавычки не поддерживаются.

### Данные ОС (`system_info.py`)

`get_username()` и `get_hostname()` берут имя пользователя и имя
компьютера у ОС (если ОС не вернула, подставляется `unknown`).
`format_title` и `format_prompt` формируют заголовок окна и
приглашение `user@host:~$`.

## Требования

- Python 3.8 или новее.
- Модуль tkinter. В Windows и macOS он входит в стандартную установку
  Python. В Debian/Ubuntu: `sudo apt install python3-tk`.
- Сторонние библиотеки не нужны.

## Сборка и запуск

Сборка не требуется. Запуск эмулятора:

```
run.bat [параметры]          # Windows
./run.sh [параметры]         # Linux / macOS
make run ARGS="параметры"    # через Makefile
```

Без скриптов (из корня репозитория):

```
PYTHONPATH=src python3 -m emulator [параметры]          # Linux / macOS
set PYTHONPATH=src && python -m emulator [параметры]    # Windows (cmd)
```

### Тестовые VFS-архивы

ZIP-архивы не хранятся в репозитории, их создаёт генератор:

```
python tools/make_vfs.py          # папка vfs_data (в .gitignore)
make vfs                          # то же через Makefile
```

| Архив | Содержимое |
|---|---|
| `minimal.zip` | один файл `hello.txt` |
| `several.zip` | несколько файлов (текст, пустой, двоичный) и каталог `docs` |
| `deep.zip` | вложенность до 5 уровней, пустой каталог, имя файла на кириллице |
| `broken.zip` | обычный текст с расширением .zip (для проверки ошибки) |
| `traversal.zip` | запись `../evil.txt` (для проверки ошибки) |

```
make test
```

```
PYTHONPATH=src python3 -m unittest discover -s tests -v    # Linux / macOS
```

### Скрипты ОС для проверки эмулятора

В папке `scripts/` лежат скрипты, которые сами создают тестовые
архивы и запускают эмулятор с разными параметрами. После закрытия
окна запускается следующий вызов. Для каждой ОС есть пары `.bat`
(Windows) и `.sh` (Linux/macOS, запуск `sh scripts/имя.sh`):

| Скрипт | Что проверяет |
|---|---|
| `test_basic` | без параметров, только `--vfs`, только `--script`, оба |
| `test_errors` | ошибочные строки скрипта, несуществующий скрипт, `exit` в скрипте, неизвестный параметр |
| `test_syntax` | запись `--параметр=значение`, другой порядок, параметр без значения, `--help` |
| `test_vfs_minimal` | минимальная VFS (один файл) |
| `test_vfs_several` | несколько файлов, каталог, пустой и двоичный файл |
| `test_vfs_deep` | вложенность не менее трёх уровней, пустой каталог |
| `test_vfs_errors` | нет архива, не ZIP, опасный путь, нет `--vfs` |
| `test_all` | все команды и режимы Этапов 1-3 (`all_commands.txt`) и `exit` |

Стартовые скрипты эмулятора в `examples/`: `basic.txt`,
`with_errors.txt`, `with_exit.txt`, `vfs_minimal.txt`,
`vfs_several.txt`, `vfs_deep.txt`, `all_commands.txt`.

## Примеры использования

Запуск с VFS и стартовым скриптом:

```
python tools\make_vfs.py
run.bat --vfs vfs_data\deep.zip --script examples\vfs_deep.txt
```

Окно покажет (фрагмент):

```
[debug] Параметры запуска:
[debug]   --vfs    = vfs_data\deep.zip
[debug]   --script = examples\vfs_deep.txt
VFS загружена в память: vfs_data\deep.zip (каталогов: 6, файлов: 7)
user@host:~$ vfs-tree
/
|-- etc/
|   |-- blob.bin (12 B)
|   `-- config.txt (11 B)
|-- home/
|   |-- guest/
|   `-- user/
|       |-- docs/
|       |   |-- archive/
|       |   |   `-- old.txt (22 B)
|       |   |-- report.txt (26 B)
|       |   `-- отчёт.txt (33 B)
|       `-- notes.txt (40 B)
`-- readme.txt (30 B)
user@host:~$ vfs-show etc/blob.bin
(двоичный файл, base64)
iVBORw0KGgr//gAB
user@host:~$ vfs-show /home/guest
vfs-show: /home/guest: это каталог
```

Интерактивный режим:

```
user@host:~$ ls -l /home
Команда: ls
Аргументы (2): -l /home

user@host:~$ foo
foo: команда не найдена

user@host:~$ exit
```

Последняя команда закрывает окно эмулятора.
